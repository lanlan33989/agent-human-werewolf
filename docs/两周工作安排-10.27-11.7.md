## 一、代码地图（四块，各自是什么）

### ① 主产品（整局体验：手机放桌子中央的那种）

- 代码：https://github.com/lanlan33989/agent-human-werewolf（根 README 是总入口）
- 一句话：**确定性规则引擎 + LLM 玩家 + 语音**的桌游对局服务。发牌/昼夜/结算/信息隔离由规则引擎管死（AI 拿不到别人的底牌），AI 只在"说哪句话、投谁"的决策点出场；夜间多个模型调用被编排成不冷场的节拍。
- 入口：仓库根 `README.md` → 启动 `start.py` → 开 `http://<主机>:8000/play`

### ② 主产品前端

- 代码：https://github.com/lanlan33989/agent-human-werewolf/tree/main/frontend
- 详细 README：https://github.com/lanlan33989/agent-human-werewolf/blob/main/frontend/README.md
- 一句话：无框架无构建的竖屏单页（`play.html` + `tableui.js` 牌桌状态机 + `speech_ui.js` 播报队列 + `rec.js` 录音）。**每 1~1.5s 轮询 `/public` 驱动一切，前端只渲染不裁决**。AI 表情动画的挂点在 `tableui.js`。

### ③ 主产品后端

- 代码：https://github.com/lanlan33989/agent-human-werewolf/tree/main/backend
- 详细 README：https://github.com/lanlan33989/agent-human-werewolf/blob/main/backend/README.md
- 一句话：FastAPI 总装（`server.py`）+ 对局 API（`game_api.py`）+ 确定性引擎（`engine.py`）+ AI 玩家（`agents.py`，prompt 组装唯一入口）+ 夜间编排（`night_driver/night_pre/night_script`）+ 语音适配层（`layers_asr/llm/tts.py`）+ 对局自动存档（`run_archive.py` → `runs/`）。

### ④ 工作台（提示词实验室，给提示词迭代用）

- 代码：页面 https://github.com/lanlan33989/agent-human-werewolf/blob/main/frontend/promptlab.html ·后端 https://github.com/lanlan33989/agent-human-werewolf/blob/main/backend/lab_api.py
- 详细 README：https://github.com/lanlan33989/agent-human-werewolf/blob/main/docs/lab-README.md
- 一句话：三列驾驶舱——**①席位**（用哪家的模型跑，可推给对局）· **②线上契约**（直接改主产品正在用的提示词，同一份无副本，保存即生效）· **③直播/回放**（真对局直播+上帝视角、任何一步回退重跑对比）。每局自动存档到 `runs/`，度量只看文件不算代码。

### 前后端怎么接（联调唯一强耦合点）

- 契约（已冻结 v1）：https://github.com/lanlan33989/agent-human-werewolf/blob/main/docs/contract.md
- 全量端点：https://github.com/lanlan33989/agent-human-werewolf/blob/main/docs/openapi.json
- 假数据：https://github.com/lanlan33989/agent-human-werewolf/tree/main/mock（`python mock/mock_server.py` 即起）
- 规矩：**协议字段以 contract.md 为准**；想加字段 → 改契约 + commit → 另一方跟进，不许口头适配。

## 二、阶段①：并行迭代（10/27 – 11/1）

### 2.1 宁晰琳 —— 提示词工程（主线，全程在工作台）

| 项 | 内容 |
|---|---|
| 每天 | 开 `http://<锦川主机>:8000/lab`（或本机 `start.py` 后 localhost） |
| 建基线 | **先跑 5 个固定测试场景各一局**（被怀疑自辩 / 第二轮投票 / 狼被同伴出卖 / 预言家报验 / 遗言），记下 `runs/` 里每局的**目录名（含 git 短哈希）**——这就是基线参照 |
| 迭代 | 第②列「载入线上契约」→ 改 → 「保存到线上」（⚠️ 下一次模型调用即生效，含进行中的局；想只影响新局就在没对局跑时保存） |
| 验证 | 快照/回退/重跑单步对比（第③列）；每版改完用**同样 5 个场景**重跑，只看 `runs/` 新目录（写明"AI 看到的信息 + AI 原话"全文） |
| 语料接入 | 杨家彦的候选池（30-50 条带标签）：做成 few-shot 的部分**先记在契约文档**，`trace.jsonl` 的 `few_shot_ids` 字段已预留（README 里有说明） |
| ⚠️ | 少数派操作都在 `docs/lab-README.md` 的"常用工作流"；第②列下方"离线沙盒"与线上不同源，定稿必须保存到线上契约 |

| 项 | 内容 |
|---|---|

| 格式建议 | 按契约里的槽位组织（哪些进 system 哪些进 user、哪些做 few-shot），宁晰琳把控 |
