## 二、阶段①：并行迭代（10/27–11/1）

### 2.1 宁晰琳 —— 提示词工程：纯 AI 对局迭代（主线）

| 项     | 内容                                                                                        |
| ----- | ----------------------------------------------------------------------------------------- |
| 做法    | 在实验台上用纯 AI 对局快照迭代，可反复跑、可回滚                                                                |
| 输入    | 杨家彦的语料候选池（30–50 条，带标签已脱敏）                                                                 |
| 交接    | 与郑锦川对齐一次提示词接口与上下文格式（**郑锦川主导**），之后不依赖主产品。〔更新〕对齐会照《工作台详细说明》过一遍即可，半小时内完成             |
| 本周目标  | 每改一版提示词，都用**同样 5 个测试场景**重跑一遍做检查（被怀疑时的自辩、第二轮投票、狼人被同伴出卖、预言家报验、遗言）；本周结束时，最后一版要在这 5 个场景里都不出问题 |
| ⚠️ 补充 | 周内先用实验台固定场景跑一遍**存基线**（可重放），之后每版对比才有参照。〔更新〕实验台已能**每局自动留档且自带版本标记**，基线与后续每版都记下留档编号即可，无需手动整理 |

### 2.2 杨家彦 —— 语料库（交付给宁晰琳）

| 项    | 内容                                                          |
| ----- | ----------------------------------------------------------- |
| 交付给谁 | **宁晰琳**——她把语料用进提示词迭代                                        |
| 交付内容 | ① 语料库清单（多少条、来源、格式）；② 候选样例池 30–50 条，每条带简单标签（身份/轮次/功能），脱敏在源头做 |
| 说明   | 以上条数和格式是**建议值**，具体挑哪些、按什么格式，**杨家彦和宁晰琳根据实际情况进行把控**           |
| 〔更新〕 | 语料接入方式以**写进提示词文本**为主（示例句、结构规则）；预留的"示例自动注入"机制暂未启用，本周不必等它 |

| 项  | 内容                              |
| -- | ------------------------------- |

| 每日自检 | 配套的自动化检查应全绿跑通。〔更新〕现有 6 处**历史遗留失败**（与最近改动无关，清单在后端说明文档），建议本轮顺手清掉，避免联调期误判 |

### 2.4 黄子凡 —— 前端：好看、按钮/图标够大、AI 表情

| -- | ----------------------------------------------------------------------------------------------------- |

## 附二：服务配置一览（ASR / LLM / TTS，可直接照着配）

> ⚠️ 仓库是**公开**的：key 的**实际值不写进任何提交进 git 的文件**（`.env` 已被排除在 git 外）。
> 实际值两个私有渠道拿：① 团队内私下传仓库根的 `.env` 文件；② 服务开着时访问 `/admin` 配置台（本机免口令，非本机只显示指纹）。key 曾泄露过一次，建议到控制台轮换后只改 `.env`。

### LLM —— AI 的大脑（发言/投票/技能决策）

| 配置项 | 填什么 | 说明 |
|---|---|---|
| `LLM_API_KEY` | `sk-…`（32 位） | DeepSeek 官方控制台（platform.deepseek.com）创建，充值后即用 |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | 公网直连，无需隧道 |
| `LLM_MODEL` | `deepseek-flash` | 按 `/v1/models` 清单实测 2.3s/句；`deepseek-v4-pro` 太慢（11s）别用在关键路径 |
| `LLM_TEMPERATURE` / `LLM_THINKING` | `0.8` / 留空 | 温度越高发言越发散；思考默认关（开了单句要等 40s+） |

### ASR —— 听真人说话（按住说话 → 文字）

| 配置项 | 填什么 | 说明 |
|---|---|---|
| `ASR` | `faster-whisper`（本地离线，**无需 key**）或 `qwen`（云端） | 当前本地 small 模型够用；云端中文黑话（金水/查杀）更准 |
| `DASHSCOPE_API_KEY` | `sk-ws-…` | 走云端（`ASR=qwen`）才需要；阿里云百炼控制台（bailian.console.aliyun.com）获取 |
| `DASHSCOPE_ASR_MODEL` | `qwen3-asr-flash` | 云端模型名（实测中文识别 1.3s/句） |

### TTS —— AI 开口说话（法官播报 + 每个玩家不同音色）

| 配置项 | 填什么 | 说明 |
|---|---|---|
| `TTS` | `qwen`（云端多音色）或 `sapi`（本地离线零成本，只有 1 个中文音色） | 汇报要区分 9 种人格 ⇒ 用 `qwen` |
| `DASHSCOPE_TTS_API_KEY` | `sk-ws-…` | 百炼的**第二把 key**（按模型授权）；留空则回落到 `DASHSCOPE_API_KEY` |
| `DASHSCOPE_TTS_MODEL` | `qwen3-tts-flash` | 实测 1.05s/句；控制台页面上的产品名和 API 模型名**不一致**，认准清单里的 |
| `DASHSCOPE_TTS_VOICE` | `Ethan` | 没配人格的座位用；人格→音色的映射已内置 |

### 填在哪里（三选一，改完下一局生效）

1. **仓库根 `.env`**（推荐，团队内私下传这个文件，重启服务生效）
2. 服务开着时访问 **`/admin` 配置台**（本机免口令；局域网手机只显示指纹，密钥不出服务）
3. **主产品封面 → 「模型与语音 Key」**（本机打开默认回填当前值；注意：对局的模型通道被工作台席位接管时，页面会提示 LLM key 暂不生效）
