## 2. 已知还没有门的界面（要加就走 §3 的流程）

- **战报正文**：现在是**服务端吐的一整份 Markdown**（`text/markdown`，`game_api.py:951`），
  浏览器里就是一页纯文本，**没有 UI 可言**。要把它做成有排版的战报页 = 新增一个界面，
  需要后端（给 HTML 或结构化 JSON）+ 前端（新场景）一起定。
- 长时间使用提醒横幅（`checkLongUse`，>2h）、录音失败兜底、WebSocket 类增值功能：
  都还没进 demo，谁加谁补一个场景。

## 3. 这一周前端 / 后端都要加东西，怎么并行（就这么办）

1. **契约先行，样例落地。** 后端要加字段/接口 ⇒ 先在 `docs/contract.md` 贴一份
   **真实返回样例**（不是描述，是 JSON），并 `@` 前端。
2. **前端不碰后端也能开工。** 前端拿这份样例在 `demo_scenes.js` 里加一个场景 +
   给 playwright 用的验收点，画廊立刻能看、能改样式。
3. **mock 跟上。** 后端同时把样例塞进 `frontend/mock/mock_server.py`（或 fixtures），
   于是 `:5501/play.html` 这条**假数据全流程**也能跑通同一个界面。
4. **联调只换数据源。** 真后端就绪后，`play.html` 去掉 `?demo=`、接真接口即可；
   渲染分支一行都不用改 —— 因为 demo 场景走的就是真实渲染管线。
5. **加完顺手做两件事**：① demo 场景带上 `title` / `note`；② 在 `dev_panels.html`
   的 `GROUPS` 里给它排个位置（不排也会在底部红条里喊你，不会悄悄漏掉）。
6. **每周两次对齐**（建议周一、周四）：一起打开画廊从头滚到尾，只问一句
   "有没有哪一屏产品里有、画廊里没有"。剩下的交给 §1 这张表。
