## 先搞清楚麦克风限制（否则一定卡住）

**浏览器只在「安全上下文」下允许网页访问麦克风** —— 也就是 **HTTPS**，或者 **localhost / 127.0.0.1**。

所以用局域网 IP + http（例如 `http://192.168.47.29:8000`）打开时，`getUserMedia` **直接不可用**，
而且**换浏览器、换手机、换电脑都一样**。这不是代码问题，是浏览器安全策略。

### 路径 1 · 本机 localhost（零配置）

```bash
cd h5
./.venv/Scripts/python.exe -m uvicorn server:app --host 0.0.0.0 --port 8000
```

电脑浏览器打开 **http://localhost:8000** —— 麦克风可用。
用电脑麦克风，能验链路、延迟、LLM 质量；**验不了「手机平放桌上」的远场**。

### 路径 2 · HTTPS + 手机（**做远场测试走这条**）

```bash
./.venv/Scripts/python.exe run_https.py
```

首次会自动生成自签名证书（SAN 已含本机 IP）。手机连同一 WiFi，打开 **https://192.168.47.29:8443**。
手机会提示「证书不受信任」——**选「继续访问」即可**，这是自签名证书的正常提示，不是错误。

### 路径 3 · 内网穿透

把本机端口暴露成公网 https 域名，手机直接打开。不用处理证书信任，代价是音频要过公网。

### 路径 4 · 仅 Android

`adb reverse tcp:8000 tcp:8000`，然后手机浏览器访问 `http://localhost:8000`。

**顺带回答了一半的 M17（黑话识别）**：金水 / 查杀 / 归票 / 平安夜 / 解药 / 站边 —— **本地 small 模型就能全对**。

> 所以上面的结果只能说明「模型可用」，不能说明「远场可用」—— 那要靠你自己测。

### 怎么做才是有效的远场测试

**关键：同一句话，录两遍，比差值。**

| 遍次 | 手机位置 | 你的位置 |
|---|---|---|
| 第 1 遍 | 手机贴到嘴边（约 30cm） | 正常坐姿 |
| 第 2 遍 | 手机平放桌上 | **你坐到桌子对面（约 1.5m）** |

说**同一句话**（例如"我是三号玩家，昨晚我没看到什么特别的"），然后对比两次的转写结果。

**为什么要这样比**：本地 whisper 的识别能力是**公共项**，两次都一样。
所以**两次之间的差异，才是"距离"造成的**。直接看绝对准确率会被模型本身的水平干扰。

### 预期与判读

| 观察 | 判读 |
|---|---|
| 两次几乎一样准 | 单机形态成立，可以继续 |
| 1.5m 那次明显变差（丢字、串音） | **单机形态存疑 → 先验多机** |
| ASR 耗时 2–10 秒 | **正常**。本地 CPU 模型就是这个速度，不代表听不清 |

⚠️ **本地 whisper 只用来判断「拾音质量」，不是最终方案。** 真做产品要换云端流式 ASR，
延迟才能压到 1 秒内。这一版的耗时数字**不能当产品的延迟指标**。

## 跑起来（推荐用一键启动器）

```bash
cd h5
./.venv/Scripts/python.exe start.py
```

它会做四件事：

1. **启动前自检** 8000 / 8443 上现在跑的是什么，是 mock 还是真 ASR
2. **停掉本项目的旧进程** —— 这一条是踩坑换来的，见下
3. 只起**一个进程**，同时监听 http 与 https ⇒ 两边配置必然一致
4. 打印手机可直接打开的地址

只看现状不动任何东西：

```bash
./.venv/Scripts/python.exe start.py --doctor
```

### ⚠️ 为什么必须只留一个进程（真实事故）

现象：手机做远场测试，近场远场**都**返回「（mock）我是三号玩家…」，看起来像"识别不出来"。

根因不是配置错，是**同一份代码跑着两套配置的进程**：

| 时间 | 进程 | 端口 | 配置 |
|---|---|---|---|
| 早 | `uvicorn server:app` | 8000 | 那时 `.env` 还没写，ASR = mock |
| 之后 | `run_https.py` | 8443 | `.env` 已写好，但**这个进程是在 .env 之前起的**，也是 mock |

手机走的是 HTTPS ⇒ 连到旧进程 ⇒ 永远是 mock 结果。

**所以现在页面顶部会直接告诉你**：「这个服务端的 ASR 是模拟的 —— 它根本不会识别你说的话」，
并显示当前服务地址，方便发现连错端口。

## 远场测试：看两个东西，不要只看转写

每次录音，服务端都会返回一组**拾音指标**（与用什么 ASR 无关）：

| 指标 | 含义 | 参考 |
|---|---|---|
| `rms_dbfs` | 整体响度 | < −55 几乎没收到；< −40 太轻 |
| `snr_db` | 说话声与底噪的差 | < 6 不像人说话；< 10 底噪偏高 |
| `clipping_pct` | 爆音比例 | > 1% 会明显伤识别 |
| `voice_ratio_pct` | 有声帧占比 | 太低说明大部分时间是静音 |

**为什么要它**：只看转写，分不清两种失败 ——

- 麦克风**没收到/收得弱**（形态问题，换 ASR 也救不了）
- 收到了但**模型不行**（换云端 ASR 就能解决）

指标能把这两件事分开。页面上的「近场 / 远场 对比」表会自动记录每次录音，
并给出最近两次的**响度差** —— 比绝对值更能说明距离的影响。

### 本地 whisper-small 在上限附近会怎样（模拟退化）

`_probe_farfield_sim.py` 把干净语音按距离衰减 + 空气高频损失 + 房间混响 + 环境噪声
处理成远场样态，再跑 ASR，算字级错误率（CER）：

| 条件 | 平均 CER | 最差句 | 完全正确 |
|---|---|---|---|
| 基准（无退化） | 1.4% | 5.6% | 3/4 |
| 近讲 30cm（−6dB, 25dB） | **0.0%** | 0.0% | **4/4** |
| 远场 1.5m（−12dB, 18dB） | **11.9%** | 22.2% | 1/4 |
| 远场 + 房间噪声（−18dB, 12dB） | 9.8% | 29.2% | 1/4 |
| 酒吧级噪声（−18dB, 6dB） | **17.4%** | **39.1%** | 1/4 |

判读：近讲完全够用；**远场会掉到约 1/10 的字错**；噪声一大，最差句接近四成字错，
而狼人杀里"金水 / 查杀"这种关键词错一个，整句意思就反了。

> ⚠️ 证据边界：这是**模拟退化**，不是真机实录；而且 whisper-small ≈ ¥0 的本地方案，
> 不代表云端流式 ASR 的上限。它只能用来说明「远场不是免费的」，不能用来定案。
> 定案只能靠真机实录 —— 也就是下面这件事。

跑法：

```bash
./.venv/Scripts/python.exe _probe_farfield_sim.py
```

## 语音播报与半双工（D5）

`/game` 页面现在会**念出来**：引擎播报（法官语速，慢）与 AI 发言（正常语速）。

- 播报开关在页面上的「语音」卡片里
- **半双工**：AI 说话时不占麦克风 —— 否则手机外放会被自己的麦克风收进去
- 说话用「按住说话」按钮：松手后先出识别文字，**确认无误再点「说这句」**

### ⚠️ 一个必须知道的物理限制：没有 AEC 就没有可靠的「插嘴检测」

我们刻意关掉了浏览器的 AEC（它会削掉发言开头、破坏齿音，对 ASR 有害）。
代价是：**手机外放的声音也会被自己的麦克风收进去**，所以用固定阈值判"有人在说话"，
必然变成 **AI 自己把自己打断**。

现在的做法是**自适应**：播报开头 350ms 先量串音水平，用它 ×1.8 当阈值；
串音偏大（> 0.08 RMS）时页面会提示"戴耳机会准得多"。

要真正做「随时插话」，只有三条路：戴耳机 / 做回声消除（但要接受 ASR 变差）/
接受阈值法（安静环境 + 手机放桌上时通常可行）。
